# 결산체크

부서별 월말 결산 자료의 요청과 제출 현황을 한 화면에서 관리하는 웹 프로그램입니다. 재무 담당자가 요청 항목을 등록하면 각 부서 담당자가 제출 완료 여부를 직접 표시하고, 모든 구성원이 같은 현황판에서 진행률과 마감 기한을 확인할 수 있습니다.

## 배포 주소

- 서비스: https://summit-eight-tau.vercel.app
- 저장소: https://github.com/hwang030915/SUMMIT_project

## 비밀번호 찾기 메일 설정

비밀번호 찾기는 가입한 이메일로 6자리 인증번호를 발송합니다. 인증번호는 3분 동안 유효하며 재전송은 60초 후 가능합니다. 번호는 API 응답이나 화면에 표시하지 않습니다. SMTP 설정이 없거나 발송에 실패하면 오류를 표시하며, 화면 표시 데모 모드로 전환하지 않습니다. 기존 `SHOW_RESET_CODE` 환경변수는 더 이상 사용하지 않습니다.

### Gmail 발신 계정 준비

1. 발신용 Google 계정에서 2단계 인증을 켭니다.
2. [Google 앱 비밀번호](https://myaccount.google.com/apppasswords)에서 SUMMIT용 앱 비밀번호를 만듭니다. 일반 로그인 비밀번호를 사용하지 않습니다. 계정 정책에 따라 앱 비밀번호를 사용할 수 없는 경우 다른 SMTP 발신 서비스를 사용하세요. [Google 공식 안내](https://support.google.com/accounts/answer/185833?hl=ko)
3. 아래 값을 Vercel 프로젝트의 Settings → Environment Variables에 추가합니다. 실제 비밀번호는 GitHub나 채팅에 올리지 않습니다.

| 변수 | Gmail 기준 값 |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_USER` | 발신 Gmail 주소 |
| `SMTP_PASS` | 발신 계정의 앱 비밀번호 |
| `MAIL_FROM` | 선택. 기본값은 `SUMMIT <SMTP_USER>`이며 발신 권한이 있는 주소만 사용 |

Production 및 사용할 Preview 환경에 설정한 뒤 **재배포**하세요. DB용 `MONGODB_URI`도 필요하며, 선택 변수 `MONGODB_DB`는 미설정 시 URI의 DB 이름 또는 `summit`을 사용합니다. 이 저장소의 Vercel Root Directory는 `frontend`입니다.

### 로컬 실행과 검증

Node.js 22에서 `frontend` 폴더로 이동하여 `npm ci`를 실행합니다. `.env.example`을 `.env.local`로 복사하고 실제 DB·SMTP 값을 입력한 뒤 `npx vercel dev`로 실행하세요. HTML만 여는 방식이나 정적 파일 서버는 API를 실행하지 않습니다.

`npm test`는 실제 DB와 메일 발송을 대체한 회귀 검사입니다. 실제 메일 수신은 별도로 다음 순서로 확인하세요.

1. 수신 가능한 본인 이메일로 회원가입합니다. 기본 시연 계정 주소는 수신 테스트에 쓰지 않습니다.
2. 비밀번호 찾기에서 가입한 이름·이메일로 인증번호를 요청합니다.
3. 받은편지함과 스팸함에서 SUMMIT 인증 메일을 확인합니다.
4. 번호를 입력하고 3분 이내에 새 비밀번호를 저장합니다.
5. 이전 비밀번호는 실패하고 새 비밀번호로 로그인되는지 확인합니다.
6. 잘못된 번호·만료·재전송·SMTP 설정 오류에서도 번호 노출 없이 안내되는지 확인합니다.

SMTP 서버의 접수 성공이 받은편지함 도착을 보장하지는 않습니다. 메일이 없다면 스팸함, 수신 주소, 발신 계정의 반송 메일을 확인하세요. TLS 연결 및 465/587 포트 설정은 [Nodemailer SMTP 문서](https://nodemailer.com/smtp)를 참고하세요.

## 해결하려는 문제

월말 결산 때 재무 담당자는 부서별 자료를 메일로 요청하고, 회신 여부를 개인 엑셀에 표시한 뒤 미제출 부서에 다시 연락합니다. 제출 전 과정을 함께 확인할 공용 화면이 없어 확인과 독촉에 매월 약 6시간이 걸립니다.

### 현재 업무 흐름

1. **요청 메일 발송**: 부서별 결산 자료와 제출 기한을 정리해 메일로 보냅니다. 약 1시간이 걸립니다.
2. **제출 여부 확인**: 메일함의 회신을 찾아 개인 엑셀 체크리스트에 표시합니다. 약 2시간이 걸립니다.
3. **독촉 및 재요청**: 미제출 또는 누락된 부서에 메신저나 전화로 다시 요청합니다. 약 2시간이 걸립니다.
4. **현황 보고**: 팀장에게 보고할 진행 상황을 다시 정리합니다. 약 1시간이 걸립니다.

> 시간은 워크시트에서 설정한 가상 수치입니다.

### 원인 분석

- 요청과 제출 현황을 확인하려면 메일함을 하나씩 열어야 합니다.
- 현황이 담당자의 개인 엑셀에만 있어 각 부서와 팀장이 진행 상황을 바로 알 수 없습니다.
- ERP는 제출된 자료의 전표 처리에 집중하며, 자료를 제출하기 전 단계는 함께 보여주지 않습니다.

**핵심 원인:** 결산 자료의 요청과 제출 상태를 모두가 함께 보는 공용 현황판이 없습니다.

## 해결 방법

재무 담당자가 결산 요청을 한 번 등록하면 각 부서 담당자가 자신의 제출 상태를 직접 갱신합니다. 구성원은 공용 현황판에서 부서별 제출 여부, 마감 기한과 전체 진행률을 확인합니다.

목표는 확인과 독촉에 드는 시간을 월 약 6시간에서 현황판 확인 약 1시간으로 줄이는 것입니다. 이 수치는 실제 사용 테스트를 통해 검증해야 합니다.

## 화면 구성

### 1. 요청 등록 화면

재무 담당자가 다음 정보를 입력합니다.

- 결산월
- 자료명
- 담당 부서
- 제출 기한
- 요청 메모

### 2. 제출 체크 화면

각 부서 담당자가 다음 정보를 입력하거나 수정합니다.

- 제출 완료 여부
- 제출자
- 메모

### 3. 공용 현황판

모든 사용자가 다음 정보를 조회합니다.

- 부서별 제출 및 미제출 현황
- 결산월 및 부서별 필터
- 제출 기한 D-day
- 기한이 지난 요청의 빨간색 강조
- 전체 진행률

## 핵심 기능과 확인 기준

| 우선순위 | 기능 | 확인 기준 |
| ---: | --- | --- |
| 1 | 요청 항목 등록 및 저장 | 새로고침한 뒤에도 등록한 요청이 남아 있어야 합니다. |
| 2 | 전체 현황 목록 조회 | 다른 PC에서도 같은 목록을 볼 수 있어야 합니다. |
| 3 | 부서별 제출 완료 체크 | 체크 직후 제출 상태가 현황판에 반영되어야 합니다. |
| 4 | 기한 임박 및 지연 강조 | 기한이 지난 요청이 빨간색으로 표시되어야 합니다. |
| 5 | 필터 및 진행률 | 필터 결과, 목록과 진행률 숫자가 일치해야 합니다. |

## 완료 조건

- 재무 담당자가 결산 요청을 입력할 수 있습니다.
- 입력한 요청이 공용 저장소에 저장됩니다.
- 새로고침하거나 다른 PC에서 접속해도 같은 데이터를 조회할 수 있습니다.
- 각 부서 담당자가 제출 상태를 변경할 수 있습니다.
- 기한과 진행률이 저장된 데이터에 맞게 표시됩니다.
- 누구나 접속할 수 있는 인터넷 주소로 배포합니다.

## 테스트 체크리스트

- [ ] 요청을 새로 등록한 뒤 새로고침해도 데이터가 유지된다.
- [ ] 다른 PC 또는 시크릿 창에서 같은 요청이 보인다.
- [ ] 제출 완료를 체크하면 현황과 진행률이 즉시 바뀐다.
- [ ] 결산월 필터가 올바르게 동작한다.
- [ ] 부서 필터가 올바르게 동작한다.
- [ ] 마감일이 지난 미제출 항목이 빨간색으로 표시된다.
- [ ] 목록의 제출 건수와 전체 진행률이 일치한다.
- [ ] 배포 주소에서 입력, 저장, 조회의 전체 흐름이 동작한다.

## 기대 효과

- 재무·회계 담당자는 메일함과 개인 엑셀을 번갈아 확인하는 시간을 줄일 수 있습니다.
- 각 부서 담당자는 자신이 제출할 자료와 기한을 바로 확인할 수 있습니다.
- 팀장은 별도의 재정리 없이 전체 진행 상황을 확인할 수 있습니다.
- 미제출 부서가 명확하게 보여 반복적인 독촉 연락을 줄일 수 있습니다.

## AI와 팀의 역할

- 불편 후보 제안 및 기존 솔루션 확인 지원

- 기능 우선순위 결정

## 시연 순서

1. 재무 담당자로 결산 요청을 등록합니다.

3. 부서 담당자로 제출 완료를 체크합니다.
